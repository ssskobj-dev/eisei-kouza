# 衛星データ解析を再現できる形で残す：記録する8項目と版の固定：製品の名前、範囲、処理の版、基準の値、道具の版、AIへの指示文。報告には「AIが書き、人が何を確かめたか」を書く

（note用の全文。「ここから有料」の行より下が有料の範囲。図は、サイトの記事の図を使う）

## この章で分かること

- 使ったデータ、範囲、処理の段階と版、基準の値、道具の版、AIへの指示文を記録し、他人があとから同じ結果を出せる形で残せるようになる
- 同じコードを半年後に動かすと値が変わる理由（データの処理の版、道具の版、「最新の1枚」）が分かる
- 報告に「AIが書き、人が何を確かめたか」を書く型と、記録の例が手に入る

## 何が分かるか

記録の型は、次のような問いに答えるために使います。

- 「去年の結果と今年の結果を比べたい。去年のコードを動かしたら、同じ場所の値が違う。どちらが正しいのか」
- 「担当者が替わった。前任者の地図を、同じ手順でもう一度作れるか」
- 「AIに書かせたと報告に書いてよいか。書くなら、何を添えれば信じてもらえるか」

答えは、「結果を残すだけでは足りない。結果を出した条件を8項目で残し、版を固定し、人が何を確かめたかを報告に書く」です。再現できない結果は、比べることも、引き継ぐことも、説明することもできません。

## しくみ

同じコードを同じ場所で動かしても、時間がたつと結果が変わることがあります。原因は、コードの外にあります。

1つ目は、**データの処理の版**です。衛星のデータは、配る側が処理のやり方を更新し、同じ観測日の製品を作り直すことがあります。Sentinel-2では、処理の版04.00から、Level-2A（大気の影響を補正した地表の反射率）の画素の値に波長帯ごとの「ずらし」が加わりました[1]。この版は2022年1月25日に始まりました[2]。ずらしを足してから倍率の10000で割る決まりなので[1][2]、「10000で割るだけ」のコードは、版が変わると値がずれます。処理の版は、製品の名前の中に「N0400」のような形で入っています[3]。Landsatでは、Collection 1の全データが2022年12月30日に利用できなくなり、Collection 2に置き換わりました[4]。Collection 2では、欠けを示す値と倍率がCollection 1と違います[5]。

2つ目は、**道具の版**です。コードが呼ぶ道具（言語や部品）は、版が上がると、何も書かなかったときの振る舞いが変わることがあります。コードは1文字も変わっていないのに、結果が変わります。

3つ目は、**「最新の1枚」**のような、動かした日に依存する指定です。半年後には、別の日の画像が「最新」です。

（ここに図：items　記録に残す8項目）

記録に残すのは、次の8項目です。

| 項目 | 何を残すか | 残さないと起きること |
|---|---|---|
| 1. 製品の名前 | 使った製品の名前を全部。衛星、観測日時、処理の版、軌道、区画が名前に入っている[3] | 「Sentinel-2、2025年夏」では、どの画像か特定できない |
| 2. 範囲 | 境界のファイルの名前と日付。座標の基準 | 境界が更新されると、区画の数も面積も変わる |
| 3. 期間 | 開始日と終了日。「最新」「直近」と書かない | 動かした日で、使う画像が変わる |
| 4. 処理の段階と版 | Level-2Aのような段階の名前と、製品の名前に入った版の番号 | 版が変わると、倍率とずらしが変わる |
| 5. 基準の値 | しきい値と、その出どころ | 「一般的な値」は、次の人が変えても気づけない |
| 6. 道具の版 | 言語と部品の名前と版の番号の一覧。AIの名前と使った日付 | 版が上がると、同じコードで結果が変わる |
| 7. AIへの指示文 | 指示文の全文と、返ってきたコードそのもの | 要約だけでは、同じコードを再び得られない |
| 8. 人が確かめたこと | 確認の一覧と結果。確かめていないこと | 「AIが書いた」だけでは、信じる根拠がない |

## 手順

1. **8項目の空欄を作る（人）。** 入れるのは、解析を始める前の指示文です。出るのは、8項目の見出しだけが並んだ記録の紙です。解析の後ではなく、前に作ります
2. **コードに記録を書き出させる（AIと人）。** 入れるのは「使った製品の名前の一覧、ずらしと倍率、しきい値、道具の版を、結果と一緒に書き出して」という指示です。出るのは、結果の横に置かれた記録のファイルです
3. **版を固定する（人）。** 入れるのは記録の6の一覧です。出るのは、次に動かすときも同じ版の道具を使う、と決めた一覧です。データ側は、製品の名前で同じ版を指定して取り直せることを確かめます
4. **人が確かめたことを書く（人）。** 入れるのは、コードと結果のレビューの一覧です。出るのは「見た観点と結果」「見ていない観点」の2つの表です
5. **報告に添える（人）。** 入れるのは8項目です。出るのは、報告の末尾の「再現のための条件」の節です

（ここに図：report　報告に書く2つのこと）

報告に「AIが書いた」と書くことは、隠すことではありません。隠すと、次の人は「人が書いた」と思って読みます。書くときは、何をAIが書き、人が何を確かめたかを対にします。「AIが書いた。人は、波長帯の番号、倍率とずらし、雲の分類の番号を公式資料と突き合わせ、ため池と森の値を確かめた。欠けた値の扱いは確かめていない」のように書きます。

## AIへの頼み方

7項目（目的、場所、期間、衛星と処理の段階、手順、出力、確かめ方）を埋めた指示文に、記録の項目を足した例です。

> **目的**：市内のため池が夏に干上がっているかどうかの候補を出し、来年の同じ時期と比べる。候補は現地で確かめる。
> **場所**：市のため池台帳の境界のファイル（ファイルの名前と日付：別添）。
> **期間**：2025年7月1日〜8月31日。
> **衛星と処理の段階**：Sentinel-2のLevel-2A。使った製品の名前を全部、結果と一緒に書き出す。
> **手順**：シーン分類で雲の影（3）、雲（8、9）、薄い雲（10）を除く。緑（B3）と近赤外（B8）から水の指数を計算する。ため池ごとに期間内の中央値を出す。
> **出力**：ため池の番号、中央値、使えた画像の枚数の表。それに加えて、記録のファイル（製品の名前の一覧、付属情報から読んだずらしと倍率、しきい値と出どころ、道具の名前と版の一覧、この指示文の全文）。
> **確かめ方**：製品の名前から読んだ処理の版を表示する。ずらしと倍率を付属情報のどこから読んだかを表示する。「最新」「直近」のような、動かす日に依存する指定を使わない。

あいまいな頼み方と、直した頼み方を比べます。

| あいまいな頼み方 | 直した頼み方 |
|---|---|
| 使ったデータを記録して | 使った製品の名前を、省略せずに全部、記録のファイルに書き出して |
| 最新の画像を使って | 2025年7月1日〜8月31日の画像を全部使って。動かす日で変わる指定はしないで |
| 再現できるようにして | 道具の名前と版の番号の一覧と、この指示文の全文を、結果と同じフォルダに保存して |

「記録して」だけでは、AIは「Sentinel-2 L2A、2025年夏」のような要約を残します。要約は、次の人が同じ画像を取り直す手がかりになりません。

## コードのレビュー観点

共通の観点（データ、実在するか、波長帯、値の倍率、雲と影、位置と座標、比べる条件、基準の値、欠けた値、面積、失敗の隠れ、学習と確認）のうち、この章で特に見るのは「データ」「値の倍率」「比べる条件」「基準の値」の4つです。

1. **動かす日に依存する指定がないか。** 「最新」「直近」「一番新しい1枚」は、半年後に別の画像を指します
2. **製品の名前が省略されていないか。** 名前の中の処理の版と軌道と区画が、記録に残っているか[3]
3. **倍率とずらしを、付属情報から読んでいるか。** 決め打ちの数字は、版が変わると合わなくなります[1]
4. **しきい値に出どころがあるか。** 「一般的に」で済ませた値は、次の人が変えても気づけません

誤りを仕込んだ抜粋です。AIは次の説明を添えて返してきます。「製品の名前の『N0400』は軌道の番号なので、記録には観測日だけあれば十分です。反射率は10000で割れば得られます。しきい値は一般的な0.3を使います。」

```
# ため池の水の候補を出し、記録を残す（誤りあり）
scenes = search(area, "2025-07-01", "2025-08-31", "S2 L2A", cloud_lt=20)
scene = scenes[-1]                              # 一番新しい1枚
green = read_band(scene, "B3") / 10000
nir = read_band(scene, "B8") / 10000
water = water_index(green, nir) > 0.3           # 一般的なしきい値
log("データ: Sentinel-2 L2A, 2025年夏")
log("しきい値: 0.3")
save(water, "result.tif")
```

誤りは4つです。

1つ目は3行目です。期間内の画像のうち「一番新しい1枚」を使っています。検索の結果の並びと、動かした日の保管の状態で、別の画像になります。正しくは、期間内の全部の画像を使うか、使う画像の名前を指定します。

2つ目は4〜5行目です。10000で割るだけで、ずらしを足していません。処理の版04.00以降の製品では、付属情報のずらしを足してから倍率で割ります[1][2]。正しくは、付属情報からずらしと倍率を読みます。

3つ目は7行目です。「Sentinel-2 L2A、2025年夏」は要約で、製品の名前ではありません。AIの説明の「N0400は軌道の番号」も誤りです。製品の名前では、「N0400」のようなNに続く4桁が処理の版、「R031」のようなRに続く3桁が軌道の番号です[3]。正しくは、使った製品の名前を省略せずに全部書き出します。

4つ目は6行目と8行目です。しきい値の0.3に出どころがありません。正しくは、出どころ（資料の名前か、答えの分かっている場所で決めた経緯）を、値と一緒に記録します。

この4つは、動かしても止まりません。記録があるように見えて、半年後に同じ地図を作れない記録です。

## 結果の目視レビュー観点

記録のファイルと、報告の末尾では、次を見ます。

- **製品の名前の一覧が、省略なしで並んでいるか。** 名前から観測日時と処理の版が読めるか[3]
- **ずらしと倍率を、付属情報から読んだと書いてあるか。** 決め打ちの「10000」だけなら、版が変わると合わなくなります[1]
- **「最新」「直近」の語が、記録と報告のどこにもないか**
- **道具の一覧に版の番号があるか。** 名前だけの一覧は、固定になっていません
- **「人が確かめたこと」に、見ていない観点が書いてあるか。** 全部確かめた、という記録のほうが疑わしい

おかしな結果の例を2つ挙げます。

**例1：半年後に同じコードを動かしたら、全部のため池の値が一律に下がった。** データ側で処理の版が変わり、ずらしが入った製品に置き換わっています[1][2]。コードは「10000で割るだけ」なので、ずらしの分だけ全体が低く出ます。製品の名前を記録していれば、名前の中の版の番号が違うことで原因が分かります[3]。記録がないと、「ため池が干上がった」と読み違えます。

**例2：前任者のLandsatの手順が、データの取得で止まる。** 記録にあるのがCollection 1の製品で、2022年12月30日に利用できなくなっています[4]。Collection 2に置き換えると取得はできますが、欠けを示す値と倍率が違うので[5]、前任者の結果とは数字が合いません。両方を混ぜた比較はしないよう、配布元も注意しています[4]。この場合、「同じ手順で作り直した」とは書けません。「Collection 2で作り直し、前の結果とは直接比べられない」と書きます。

**言えること、言えないこと。** 言えるのは、「この8項目のもとで、この結果が出た」ことです。8項目がそろっていれば、他人が同じ条件で取り直して確かめられます。言えないのは、「別の版のデータや道具でも同じ結果になる」ことです。版が変わったら、同じ条件とは言えません。比べるときは、どちらかに版をそろえて作り直します。

## 向かない条件

- **製品の名前を取り出せない取り方をしている。** 画面で切り抜いた画像や、名前を付け替えた複製は、もとの製品を特定できません
- **境界のファイルが日々更新されている。** 使った日の複製を保存しないと、範囲を再現できません
- **AIの返答を保存していない。** 指示文の全文と返ってきたコードがないと、同じコードを再び得る手段がありません。AIは同じ指示にも違うコードを返します
- **有償の商用データを使うとき。** 8項目は変わりません。変わるのは、名前と版の決まりが契約の仕様書にあることと、データを他人に渡せるかが利用条件で決まることです
