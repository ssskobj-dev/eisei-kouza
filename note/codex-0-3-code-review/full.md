# 衛星データ解析コードの読み方：書けなくても確かめられる5つの塊と12のレビュー観点：取る、選ぶ、計算する、まとめる、出す。AIに1行ずつ説明させ、別の頼み方でもう一度書かせて突き合わせる

（note用の全文。「ここから有料」の行より下が有料の範囲。図は、サイトの記事の図を使う）

## この章で分かること

- AIが書いた衛星データの解析コードを、「取る、選ぶ、計算する、まとめる、出す」の5つの塊に分けて読み、要所を確かめられるようになる
- AIに1行ずつ説明させる方法と、別の頼み方でもう一度書かせて突き合わせる方法の使い分けが分かる
- どの章の解析にも当てる、共通のレビュー観点12項目を一覧で持てる

## 何が分かるか

コードのレビューの型は、次のような問いに答えるために使います。

- 「コードを書けない自分が、AIの書いた数十行をどこまで確かめられるか」
- 「全部は読めない。どの行を見れば、大きな誤りを拾えるか」
- 「AIに『正しいか確認して』と聞いたら『正しいです』と返ってきた。これで足りるか」

答えは、「全部を読まなくてよい。塊の境目にある数行と、12項目の観点に当たる行だけを見る」です。AIの「正しいです」は確認ではありません。確認は、公式資料と突き合わせた人だけができます。

## しくみ

衛星データの解析コードは、長く見えても、やっていることは5つに分かれます。データを**取る**、使う画素を**選ぶ**、値を**計算する**、区画や期間で**まとめる**、表や地図に**出す**。どの衛星でも、どの指数でも、この順番は変わりません。

（ここに図：blocks　コードを5つの塊に分けて読む）

塊に分けると、見る場所が決まります。誤りの多くは、塊の中ではなく、塊の境目で起きます。取った値の倍率が違うまま計算に渡す。選んで除いたつもりの画素が、まとめる段で平均に混ざる。こうした境目の数行を見るだけで、大きな誤りの大半は拾えます。

AIは、この境目を自信のある口調でつなぎます。たとえば、Sentinel-2のLevel-2A（大気の影響を補正した地表の反射率）では、画素の値に波長帯ごとの「ずらし」を足し、「倍率」の10000で割ると反射率になります[1][2]。一方、Landsat 8と9のCollection 2 Level-2の地表反射率は、画素の値に0.0000275を掛けて0.2を引きます[3]。衛星が違えば決まりが違います。AIは、この2つを混ぜて、どちらにも見える1行を書くことがあります。

## 手順

（ここに図：flow　全部を読まずに確かめる4つの手順）

1. **5つの塊に区切る（人）。** 入れるのはAIのコードです。出るのは、「ここまでが取る、ここからが選ぶ」と印を付けたコードです。区切れない行があれば、何をしているか分からない行なので、次の手順でまず聞きます
2. **塊の境目を1行ずつ説明させる（AIと人）。** 入れるのは境目の数行です。出るのは、「この行は、何を入れて、何を出すか」の説明です。説明の中の数字や名前（波長帯の番号、倍率、分類の番号）を書き出します
3. **12項目の観点を当て、公式資料で確かめる（人）。** 入れるのは書き出した数字と名前です。出るのは「資料と合う」「違う」の判定です。合わない行は、資料のどこを見て直すかを添えてAIに直させます
4. **別の頼み方でもう一度書かせ、突き合わせる（AIと人）。** 入れるのは、言い回しを変えた同じ指示文です。出るのは2本目のコードです。1本目と違う箇所が、AIが補った箇所です。違いの1つ1つに、どちらが正しいかを資料で決めます

4の突き合わせで、2本が同じだったからといって正しいとは限りません。よくある誤りは、2本とも同じように誤ります。突き合わせは「違う箇所を見つける」ための手順で、「合っている箇所を信じる」ための手順ではありません。

## AIへの頼み方

レビューのための頼み方は、コードを書かせる頼み方とは別に用意します。7項目（目的、場所、期間、衛星と処理の段階、手順、出力、確かめ方）を埋めた指示文の例です。

> **目的**：市内の農地の区画ごとに植物の茂り具合を比べ、茂りの少ない区画の候補を出す。候補は現地で確かめる。
> **場所**：区画の境界のファイル（別添）。座標の基準はファイルの付属情報に書いてあるものを使う。
> **期間**：2025年5月1日〜6月30日。
> **衛星と処理の段階**：Sentinel-2のLevel-2A（大気の影響を補正した地表の反射率）。
> **手順**：シーン分類で雲の影（3）、雲（8、9）、薄い雲（10）の画素を除く。赤（B4）と近赤外（B8）から植生の指数を計算する。区画ごとに、除いた画素を数に入れずに平均する。
> **出力**：区画の番号、平均値、使えた画素の数の表。
> **確かめ方**：コードを「取る、選ぶ、計算する、まとめる、出す」の5つに区切って見出しを付ける。塊の境目の行は、何を入れて何を出すかを1行ずつ説明する。反射率に直すときの、ずらしと倍率の値と、それを公式資料のどこで確かめたかを書く。森の区画が高く、ため池の区画が低く出ることを先に確かめる。

あいまいな頼み方と、直した頼み方を比べます。

| あいまいな頼み方 | 直した頼み方 |
|---|---|
| このコードは正しい？ | このコードを5つの塊に区切って、塊の境目の行だけ、何を入れて何を出すか説明して |
| 反射率の計算は合ってる？ | 反射率に直す行で使った、ずらしと倍率の値を書いて。それをSentinel-2の公式資料のどこで確かめたか、資料の名前を書いて |
| 雲は除いてある？ | 雲として除いた分類の番号を全部書いて。除いた画素は、平均の分母に入っているか、入っていないかを書いて |

「正しい？」と聞くと、AIは「正しいです」と答えます。AIは自分のコードを疑う材料を持っていません。「何を入れて何を出すか」「どの資料で確かめたか」と聞くと、答えの中に、人が資料と突き合わせられる数字と名前が現れます。

## コードのレビュー観点

共通のレビュー観点は12項目です。どの章の解析でも、この順に当てます。

| 観点 | 何を見るか | 主に見る塊 |
|---|---|---|
| 1. データ | 指示した衛星、処理の段階、期間のデータを読んでいるか | 取る |
| 2. 実在するか | 関数、引数、データの名前が実在するか。AIは、ありそうな名前を作る | 取る |
| 3. 波長帯 | 波長帯の番号が、使う衛星の公式資料と合うか | 取る |
| 4. 値の倍率 | 画素の値を物理的な値に直す倍率とずらしが、その衛星の決まりか | 取る |
| 5. 雲と影 | 雲、雲の影、薄い雲を除いているか。分類の番号は公式の表と合うか | 選ぶ |
| 6. 位置と座標 | 範囲の座標の基準と、緯度と経度の順番が、データとそろっているか | 選ぶ |
| 7. 比べる条件 | 2時期を比べるとき、季節、衛星、処理の段階がそろっているか | 選ぶ |
| 8. 基準の値 | しきい値の出どころが書いてあるか。「一般的に」で済ませていないか | 計算する |
| 9. 欠けた値 | 除いた画素を「0」にしていないか。欠けは欠けのまま、平均の分母から外しているか | まとめる |
| 10. 面積 | 画素の数に掛ける1画素の面積が、使った波長帯の画素の大きさか | まとめる |
| 11. 失敗の隠れ | エラーを握りつぶして0や空を返していないか。処理できた件数を出しているか | 出す |
| 12. 学習と確認 | 機械学習で、確認用のデータが学習に混ざっていないか | 計算する |

この章で特に見るのは、4の値の倍率、5の雲と影、9の欠けた値の3つです。

誤りを仕込んだ抜粋です。AIは次の説明を添えて返してきます。「Level-2Aの反射率は、画素の値に0.0000275を掛けて0.2を引いて求めます。雲は分類の8と9なので、その画素は0にして平均から外します。」

```
# Sentinel-2 Level-2A から、区画ごとの植生の指数の平均を出す（誤りあり）
red = read_band(scene, "B4") * 0.0000275 - 0.2    # 取る
nir = read_band(scene, "B8") * 0.0000275 - 0.2    # 取る
scl = read_band(scene, "SCL")                     # 取る
bad = (scl == 8) | (scl == 9)                     # 選ぶ
index = (nir - red) / (nir + red)                 # 計算する
index[bad] = 0                                    # 選ぶ（除いたつもり）
table = mean_by_parcel(index, parcels)            # まとめる
save_csv(table, "result.csv")                     # 出す
```

誤りは3つです。

1つ目は2〜3行目の**値の倍率**です。0.0000275と0.2は、Landsat Collection 2 Level-2の地表反射率の決まりです[3]。Sentinel-2のLevel-2Aでは、画素の値に波長帯ごとのずらし（付属情報のBOA_ADD_OFFSET）を足し、倍率（QUANTIFICATION_VALUE、10000）で割ります[1][2]。ずらしは処理の版04.00から入り、この版は2022年1月25日に始まりました[2]。正しくは、付属情報からずらしと倍率を読み、「（画素の値＋ずらし）÷倍率」と書きます。

2つ目は5行目の**雲と影**です。8と9は雲（確からしさが中と高）ですが、3の雲の影と10の薄い雲が残っています[2]。正しくは、3、8、9、10を除きます。

3つ目は7行目の**欠けた値**です。除いたつもりの画素を0にしています。0は「値がない」ではなく「指数が0」という値なので、8行目の平均に分母ごと混ざります。正しくは、欠けを示す印（欠損値）を入れ、平均では欠けを分母から外し、使えた画素の数を表に出します。

AIの説明は3つとも自信のある口調でした。1つ目は別の衛星の決まり、3つ目は「外します」と言いながら外していない書き方です。3つとも、コードを動かしても止まりません。表はできて、地図も描けます。だから、資料と突き合わせる人が要ります。

## 結果の目視レビュー観点

表と地図では、次を見ます。

- **答えの分かっている区画の値。** 森が高く、ため池が低いか。順番が逆なら、倍率か波長帯が疑わしい
- **値の範囲。** 植生の指数は−1から1の間の値です。全部の区画が負なら、倍率とずらしが別の衛星の決まりです
- **使えた画素の数。** 区画ごとの画素の数が表にあるか。ないなら、欠けた値の扱いを確かめられません
- **雲の多い日の値。** 期間内の画像のうち、何枚を使ったか。農研機構の資料では、2018年4〜6月の約2か月に24回の観測があり、晴天は8回でした[4]。使えた枚数が少ないのは、異常ではなく、記録すべき条件です

おかしな結果の例を2つ挙げます。

**例1：全部の区画が負の値で、森がため池より低い。** Landsatの決まりで反射率に直したためです。Sentinel-2の画素の値は反射率を10000倍した整数なので[2]、0.0000275を掛けて0.2を引くと、赤も近赤外も負の小さな値になります。負どうしで指数を計算すると符号が反転し、森が低く出ます。地図は色がついて見えますが、森を先に見れば気づけます。

**例2：雲の縁にかかった区画だけ、平均が0に近い。** 除いたつもりの画素が0として平均に混ざったためです。雲の縁は直線ではなく、区画の境とも関係がありません。雲に半分かかった区画の平均は、本当の値の半分近くまで下がります。「茂りが少ない候補」の上位に、雲の縁の区画が並びます。

**言えること、言えないこと。** 言えるのは、「5つの塊の境目の行が指示どおりに書かれ、12項目の観点で公式資料と合い、答えの分かっている区画で予想どおりの値が出た」ことです。言えないのは、「コードに誤りがない」ことです。レビューは、見た観点について誤りがなかったことしか保証しません。見ていない観点は、見ていないと書きます。

## 向かない条件

- **コードが5つの塊に区切れない。** 1つの行で取る・選ぶ・計算するをまとめて書いてあると、境目がありません。AIに「塊ごとに分けて書き直して」と頼んでから読みます
- **公式資料が見つからない仕様。** 倍率や分類の番号の出どころが資料で確かめられないときは、その行は「確かめていない」として残します
- **AIが参照先を示せない。** 「どの資料で確かめたか」に資料の名前が返ってこないときは、AIが補った値です。人が資料を探すか、値を使わない設計に変えます
- **有償の商用データを使うとき。** 5つの塊と12項目は変わりません。変わるのは、4の値の倍率と3の波長帯の出どころが、公式の公開資料ではなく、契約で受け取った仕様書になることです
