# 出力の型：市場レポート

テーマ（ユースケース）と切り口の組み合わせで1本書く。読者は、衛星データを扱い始めたコンサルタントと、宇宙関連のコンサルティング会社の担当者（`patterns/audiences.yaml` の `consultant`）。顧客への説明や提案書にそのまま使える材料を渡す。

## 書く前に

1. `reports/topics.yaml` のテーマの `memo` を読む
2. `patterns/report_angles.yaml` の該当する切り口の `question` と `include` を読む
3. `data/market-report-2026-10/` の該当する章（切り口の `sources`）を、下調べとして読む
4. そこに挙がっている出典の原文を開いて、数字と事実を確かめる。足りなければ新しく調べる。**下調べメモの数字を、原文を見ずに写さない**
5. 同じテーマの、すでに書かれた切り口（`reports/<テーマのid>/`）を読み、内容が重ならないようにする

## 構成（2,500〜4,000字）

1. **この記事で分かること**（3点まで）
2. **結論**：切り口の `question` への答えを、3〜4文で先に言う
3. **本文**：切り口の `include` の項目を、節に分けて書く。数字は表かグラフにまとめる
4. **数字の読み方**（市場規模や金額を扱う記事では必須）：誰の推計か、何を含むか、いつの時点か。推計に幅があるときは幅のまま示す
5. **コンサルタントへの示唆**：顧客に説明するときの要点を3つまで
6. **関連する記事**：同じテーマの他の切り口、講座の該当する章
7. **出典**
8. **要確認**

## 数字と事例の決まり

- 市場規模は、**出どころ、対象の範囲、年**を必ず添える。調査会社の予測は、公開されている要約の数字だけを使い、「〜の推計では」と書く
- 推計が複数あるときは、1つに決めず、並べて幅を見せる
- 有料の報告書の中身、価格表、非公開の契約金額は書かない
- 事例は、発表元の資料で確かめたものだけを書く。**実証**か**本格運用**かを必ず区別する
- 企業を取り上げるときは、公表されている事実だけを書く。評価や推奨をしない
- 「〜と見られる」「〜と期待される」で終わる文は、誰の見方かを書く

## 図とグラフ

`figures/report-<テーマのid>-<切り口>.yaml` に書き、`python scripts/figures.py report-<テーマのid>-<切り口>` で作る。3〜5枚。

- 市場規模の比較や推移：`bar`
- 推計の幅：`range`
- 事例やプレイヤーの整理：`cards`
- 役割の関係や流れ：`flow`、`split`

グラフには、出どころと年を `source` に必ず書く。

## 冒頭の設定

```yaml
---
title: "インフラ・地盤監視：国内の事例"
subtitle: "誰が、何に、どう使っているか"
description: "一覧に出る1〜2文の要約"
date: 2026-10-12
categories: [インフラ・地盤監視, 国内の事例]
---
```

## 保存先と、あわせて作るもの

- 本文：`reports/<テーマのid>/<切り口>.qmd`（手本：`reports/infra/cases-japan.qmd`）
- note用の要約：`note/report-<テーマのid>-<切り口>/article.md`。`patterns/outputs/note.md` の型で、1,200〜1,800字。見出し画像は `kind: report`、図は本文から1〜2枚選ぶ
