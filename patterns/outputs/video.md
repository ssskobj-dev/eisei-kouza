# 出力の型：動画（講義、ユースケース解説）

台本は `video/<id>/script.yaml`。`python scripts/video.py <id>` で、動画（mp4）、説明欄（description.txt）、全文（transcript.md）、サムネイル（thumbnail.png）ができる。動画ファイルはリポジトリに置かない。

## 種類

| 種類 | id | 元になる記事 | 長さ | 場面の並び |
|---|---|---|---|---|
| ユースケース解説 | `usecase-<slug>` | `casebook/<slug>.qmd` | 4〜6分 | 表紙 → どこで誰が何のために → 業務の流れのどこに入るか → 衛星と人の分担 → 何を決める材料になるか → 限界 → 無償衛星でどこまで → 有償画像の概算 → 向き不向き → 締め |
| 講義（講座の章） | `lecture-<章のid>` | `learn/<シリーズ>/<章のid>.qmd` | 8〜12分 | 表紙 → できるようになること → 本文の節（3〜5） → 一緒にやってみよう → 手順のまとめ → 宿題（ケース問題） → 締め |
| 講義（解析教材） | `codex-<章のid>` | 解析教材の章（原稿ができてから） | 8〜15分 | 表紙 → できるようになること → 本文の節 → 一緒にやってみよう → 手順のまとめ → 宿題 → 締め |

投稿は自動。台本が main に入ると、`video` ワークフローが毎時の見回りで未投稿の台本を見つけ、動画を作って投稿する。フォルダ名が `-en` なら英語チャンネル、それ以外は日本語チャンネル。公開範囲は public。台本に `publish: false` と書けば投稿しない（試作用）。

## 守ること（根拠は、視聴の継続と記憶に関する研究。詳しくは会話の記録）

1. **冒頭10秒で、問いと答えの要点を言う**。表紙の `say` は「〜はあるか。答えは〜です。」で始める。シリーズ名や挨拶から始めない
2. **呼びかけは1本に1つ**。締め（`cta`）には `action`（1文）と `url` を1つだけ書く。ユースケース解説はRFPと相見積もりの相談、講義はサイトの章ページ
3. **通し番号**。`number` と `total` を書く（ユースケースは `data/usecases.yaml` の順番と221、講義は章の番号と30）
4. **サムネイルの文字は4語以内**。`thumb` に10字以内の短い文を書く
5. **全文と章立ては自動でできる**。`transcript.md` を記事のページに「動画の全文」として載せる。`description.txt` を投稿の説明欄に貼る
6. **サウンドロゴ**は最初の場面に自動で入る。消さない
7. **数字と事例は、元の記事にあるものだけ**。記事にない数字を台本で足さない。有償画像の概算は「仮定：」を付け、公開価格の出どころと日付を `credits` に書く
8. **声**は `video/voices.yaml` の名前で指定する。日本語は VOICEVOX、英語（`lang: en`）は Piper から選ばれる。シリーズや言語ごとに固定してよい。表記は自動で末尾に入る
9. **英語版**：台本に `lang: en` を足すと、英語の声・英語の表記・単語での折り返しになる。図は日本語の文字が入るので、英語版では表・手順・箇条書きで作る。投稿は英語チャンネル（`--channel en`、Secretは `*_EN`）
9. できた動画を開いて、最初の場面、コードの場面、締めの場面を見て、文字のはみ出しと字幕の切れがないか確かめる

## 題名（SEO）と、資格の案内（必須）

**題名は検索で見つかるように書く**（YouTube の検索と関連動画に効く）。
- **キーワードを先頭近くに**：日本語は「衛星データ」「SAR」「Sentinel」のいずれか、英語は「satellite data」「SAR」「Earth observation」のいずれかを含める。無いと `video.py` が末尾に「【衛星データ活用】」「| Satellite Data」を自動で足すが、先頭にある方が強い
- **具体的に**：誰が・何を・どれだけ（数字）。「〜について」「〜とは」だけにしない
- **長さ**：日本語は40字以内、英語は70字以内（検索結果で切れない）
- 画面に出す題名と検索用の題名を分けたいときは、台本に `yt_title:` を書く（YouTube にはそちらが使われる）
- タグは自動（言語ごとの定番＋`kicker`＋`series`）。足したいときは台本に `tags: [...]`

**資格の案内は全動画の最後に必ず入る**（`video.py` が自動で足す。台本に書かなくてよい）。
「衛星データ解析」「衛星データビジネス」の2つの資格が取得できる、という場面で、名前とリンクは `_variables.yml` の `cert` から取る。概要欄にも案内とリンク（utm 付き）が入る。外したいとき（試作など）だけ台本に `cert: false`。

## 音声、冒頭の紹介、概要欄（自動で入る）

- **話す速さ**は標準 1.2 倍（`video.py` の `SPEED_DEFAULT`）。台本に `speed:` を書かない（書くと上書きされる）
- **日本語の声**（VOICEVOX）：抑揚 1.15、文の前後に短い間。英字（SAR、InSAR、Sentinel-1、AI、GIS など）は `video.py` の `READINGS_JA` で読みに直してから合成する（字幕は元のまま）。読みが変な語を見つけたら `READINGS_JA` に足す
- **英語の声**（Piper）：声の揺らぎを少し上げて平板さを減らしている（`voices.yaml` の `noise`、`noise_w` で声ごとに調整できる）
- **冒頭の紹介**：表紙（問いと答え）の直後に「Satellite to Decision とは」の場面が自動で入る（市場レポート、資格試験、活用事例・学習・RFP相談、サイトのURLとQRコード）。表紙より前に出したいときは台本に `intro_first: true`、外すときは `intro: false`。文言は `video.py` の `L` の `intro_*`
- **資格の案内**（最後）にも、資格ページのQRコードが入る
- **概要欄**（description.txt）は、題名 → この動画の内容（summary）→ 呼びかけ → 資格の案内 → Satellite to Decision について（概要と提供しているもの、サイトと資格のリンク）→ 章立て → 出典と表記、の順で自動生成される。summary は概要欄の「この動画の内容」にそのまま出るので、2〜3文で動画の要点を書く

## 場面の種類

cover、bullets、figure、table、code、prompt、steps、cta。項目は `scripts/video.py` の各関数を参照。

## 英語の事例動画（海外向け）

英語チャンネルには、海外（`region` が「海外」「両方」）の事例を優先して動画にする。もとにするのは、**日本語で公開済みのユースケース記事**（`casebook/<slug>.qmd`）。公開済みの記事を使うことで、事実と出典が確認済みのものだけを英語にする。

- 候補は `python scripts/build.py envideos` で出る（公開済み・海外/両方・英語動画が未作成）
- 台本は `video/usecase-<slug>-en/script.yaml`。`lang: en`、`voice` は Ryan か Joe（海外向けはUS発音）
- 中身は日本語版と同じ事実。数字は記事にあるものだけ。費用の概算は「仮定：」で、公開価格の出どころと日付を `credits` に書く
- `source_url` を自分で開いて、事例と数字を確かめてから書く
- 図は日本語の文字が入るので使わない。表・手順・箇条書きで作る（手本：`video/usecase-chusankan-patrol-en/script.yaml`）
- 投稿は英語チャンネルに自動。`video/<id>-en/script.yaml` が main にマージされると、`video` ワークフローの push トリガーが動画を生成して英語チャンネルに公開（public）で投稿する。手動で上げたいときだけ Actions から `channel: en` を選んで実行する

## 英語の市場レポート動画（海外向け）

英語チャンネルには、事例だけでなく市場レポート（海外の市場・プレイヤー・制度）も動画にする。世界・海外に関わる切り口だけを対象にする。

- 対象の切り口は `patterns/report_angles.yaml` で `en_video: true` を付けたもの（世界の市場、海外の事例、主なプレイヤー、使うデータと手法）
- 候補は `python scripts/build.py enreports` で出る（テーマ × 海外向けの切り口で、英語動画が未作成のもの）
- 台本は `video/report-<テーマid>-<切り口>-en/script.yaml`。`lang: en`、`voice` は Ryan か Joe（US発音）。`series: MARKET`、`kicker: Market report`
- もとにする素材は `data/market-report-2026-10/` の、その切り口の `sources` に挙がった章。**下調べメモの数字をそのまま写さない**。必ず出典の原文を開いて、数字・年・出どころを確かめてから書く。確かめられない数字は台本から外し、`credits` に理由を書く
- 市場規模や金額は、**誰の推計か・何を含むか・いつの時点か**を必ず言う。推計に幅があるときは幅のまま言う。有料の報告書の中身・価格表・非公開の契約金額は出さない
- 事例は、発表元の資料で確かめたものだけ。**実証（pilot）か本格運用（in service）か**を区別して言う
- 特定の事業者を勧めない。会社名は、公表されている事実の範囲で挙げる
- 締め（`cta`）は、RFPと相見積もりの相談（ユースケース動画と同じ窓口）。`action` は1文、`url` は1つ
- 図は使わず、表・手順・箇条書きで作る。長さは4〜7分、場面の並びは：表紙（問いと答え）→ 要点3つ → 本文の節（切り口の `include`）→ 数字の読み方 → コンサルへの示唆 → 締め（手本：`video/report-infra-cases-overseas-en/script.yaml`）

## 日本語の講義動画（講座の章から）

日本語チャンネルには、公開済みの講座の章を講義動画にする。読者が「読む」代わりに「聞いて、一緒にやって、宿題で定着させる」ための動画。

- 候補は `python scripts/build.py javideos` の「講義動画」で出る（公開済みの章で、動画が未作成のもの）
- 台本は `video/lecture-<章のid>/script.yaml`。`series: LEARN`、`kicker` は章の属する講座名（例：`衛星サービスの選び方と使いこなし`）。声は `もち子`
- 中身は章と同じ事実だけ。章にない数字を足さない。章の `_variables.yml` 参照（`{{< var >}}`）は、値を確かめて台本に書く
- **一緒にやってみよう**：章の手順やチェックの中から1つを選び、読者が手元で数分でできる形にして、台本の中で実際にやって見せる（「まず○○を開いて、△△を見て、□□と比べる」）
- **宿題**：同じ章のケース問題（`learn/quiz/<章のid>.qmd`）から1問を出す。答えは動画では言わず、「答えと解説はサイトのケース問題で」と章のページへ誘導する
- 図は日本語なので使ってよい（`figures/<章のid>.yaml` にある図を `figure` 場面で使う）。表・手順・箇条書きも使う
- 締め（`cta`）は、章のページ（`https://ssskobj-dev.github.io/eisei-kouza/learn/<シリーズ>/<章のid>.html`）。呼びかけは1つ
- 手本：`video/codex-0-2-prompting/script.yaml`（場面の並びと「一緒にやってみよう」「宿題」の作り方）
