# 台本の点検の観点（別の目で見る）

台本（`video/<id>/script.yaml`）を書いたあと、書いた本人とは別のセッションに、**台本と、章の原稿（またはユースケース記事）と、その出典の一覧**を渡して点検させる。点検する側は、次の観点で「印」を付け、直し方を書く。書いた側は、印を直してから `python scripts/verify_script.py` を通し、PR にする。

点検は、2026年11月の植生指数の動画への利用者の指摘（A1〜A10、B1〜B9）をもとに作った。

## A. 事実・数値（必ず直す）

| 観点 | 見ること |
|---|---|
| A1 計算 | 作例の数字が、章の公式の値（ずらし、倍率、区切り）で実際に計算した値になっているか。計算式を credits に書いているか。「それらしい数字」を置いていないか |
| A2 言い切り | 「一律にずれる」「必ず〜に収まる」のような言い切りが、条件付きで正しいだけではないか。条件（反射率が0以上なら、など）を添えているか |
| A3 欠け | 欠けた値の扱い（値0、分母0、NaN）が、処理の順番と合っているか。印を付ける段階が正しいか |
| A4 具体値 | 公式の値（ずらし−1000、倍率10000、SCLの番号、画素の大きさ、周期）を数字で言っているか。「足す」とだけ言って値を言わない、になっていないか。入手先による違い（補正済みのデータがある、など）に触れているか |
| A5 画素の大きさ | 大きさの違う画像を重ねるとき（SCL 20m と B4 10m など）、合わせる手順を言っているか |
| A6 番号 | 除く分類、波長帯域の番号、軌道の向きなどが、公式資料と一致しているか。画面とナレーションで食い違っていないか |
| A7 削るべき断定 | 「逆なら〜」のように、別の場面の説明と矛盾する言い方が残っていないか |
| A8 出典 | 固有の事例（北海道の小麦、など）に、章のページで確認できる出典があるか。無ければ削る |

## B. 初心者向けの分かりやすさ

| 観点 | 見ること |
|---|---|
| B1 用語の統一 | 章の中心の用語（NDVI など）が、「指数」「植生の指数」「NDVI」と混在していないか。初出で1文ずつ説明しているか（画素、反射率、欠け、偏波、真値 など） |
| B2 結論を先に | 表紙の「答えは」が1文で長すぎないか。結論を短く言い、作業は3つに分けて後から |
| B3 時系列 | 「AIの説明どおり」のように、まだ出ていないものを指していないか |
| B4 未定義の参照 | 「7項目」「共通の観点」のように、動画の中で定義していないものを指していないか。出どころ（章のページ）を言っているか |
| B5 擬似コード | 「説明用の擬似コード」と明示しているか。行番号で指しているか。関数名を1文字ずつ読んでいないか |
| B6 順序 | 誤りの説明の順が、直前の場面で見た順（上から）と一致しているか |
| B7 役割分担 | 画面の箇条書きをナレーションが丸読みしていないか。画面は要点、ナレーションは理由と例 |
| B8 抜けた説明 | 値の範囲の片側（−1側、負になる場合）など、聞いて疑問が残る抜けがないか |
| B9 選択肢の長さ | 宿題の選択肢の長さがそろっているか（正解だけ長い、になっていないか） |
| B10 話し言葉 | ナレーションを声に出して読んで、翻訳調・名詞止めの列挙・観点名の読み上げが無いか。1場面に1回は聞き手への問いかけがあるか |
| B11 具体例 | しくみ・理由の場面に、章の数字か場面を使った「たとえば」が1つ以上あるか |

## 点検の出力

```
## 場面n「見出し」
- A1：…（直し方）
- B7：…（直し方）
```

印の無い場面は書かない。最後に「必ず直す（A）」の件数と「望ましい（B）」の件数を書く。
