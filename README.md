# 衛星データ実務講座

衛星データの強み、限界、現実的な落とし所を、使う側の立場で解説する教材です。章立てとパターンを書くと、原稿、ケース問題、note用の下書き、サイト、PDFができます。

## 人が触るファイル

| 場所 | 中身 | いつ触るか |
|---|---|---|
| `syllabus/` | 章（部品）の一覧。題名、型、読者、目標、入れる内容 | 章を足す、直すとき |
| `courses/` | 講座の定義。部品を並べる順番 | 講座を作る、顧客別に組み替えるとき |
| `patterns/` | 章の型、読者、深さ、強み、落とし所、出力の型、文体 | 書き方を変えるとき |
| `_variables.yml` | 衛星の仕様など、変わりやすい値 | 値が変わったとき |
| `data/sources.yaml` | 根拠にする公的資料の一覧 | 資料を見つけたとき |
| `design/` | PDFとサイトのデザイン（色、見出し、目次、表紙） | 見た目を変えるとき |
| `data/usecases.yaml` | ユースケースの一覧（221件）。記事はこの表の上から順に書かれる | 順番を変える、足す、外すとき |
| `usecases/` | ユースケースの記事。1件につき1本 | （自動で作られる） |
| `reports/topics.yaml` | 市場レポートのテーマ（ユースケース）の一覧 | テーマを足す、順番を変えるとき |
| `reports/` | 市場レポートの本文。テーマごとのフォルダに、切り口ごとに1本 | （自動で作られる） |
| `data/market-report-2026-10/` | 市場レポートの下調べ用のメモ | 元のレポートを更新したとき |
| `note/` | note記事。1記事1フォルダで、下書き、見出し画像、図が入る | 投稿するとき |
| `figures/` | 章ごとの図の内容（`<章のid>.yaml`）。SVGは自動で作られる | 図を足す、直すとき |

それ以外（`chapters/`、`quiz/`、`note/`、`slides/`、`workbook/`）は生成されるものです。

## 組み合わせられるパターン

| 軸 | 選択肢 | 指定する場所 |
|---|---|---|
| 章の型 | 基礎、ユースケース、実務、事例、比較、質問集 | 部品の `type` |
| 読者 | 測量の技術者、同 経営者、営農指導員、農業法人、農業委員会、インフラ管理者、一般 | 部品の `audience`、講座の `override` |
| 深さ | 概要、標準、実務 | 部品の `depth`、講座の `override` |
| 強み | 広域、過去履歴、遠隔、可視化、客観性 | 部品の `strengths` |
| 落とし所 | 絞り込み、併用、向いた対象から、変化を見る、無償から、定期監視から、言えないことの明示、外注から | 部品の `tradeoffs` |
| 出力 | note記事、ケース問題、研修スライド、ワークブック | 部品の `outputs` |
| 図解 | 分担、要点カード、手順、絞り込み、向き不向きの帯、測れる向き | `figures/<章のid>.yaml` の `type` |

どの軸も、`patterns/` にファイルや項目を足せば選択肢が増えます。

## よくある作業

**市場レポートのテーマを足す**：`reports/topics.yaml` の末尾に `- name: テーマ名` を足す。上から順に、1テーマにつき8本（切り口ごとに1本）作られます。

**章を足す**：`syllabus/` に部品を書き足し（`status: todo`）、`courses/` の並びに id を入れる。Claudeに「未作成の章を作って」と頼む。

**分野を足す**：`syllabus/<分野>.yaml` と `courses/<分野>.yaml` を作る。必要なら `patterns/audiences.yaml` に読者を足す。

**顧客別の研修テキストを作る**：`courses/example-custom.yaml` をまねて部品を並べ、`python scripts/build.py course <id>` を実行する。`custom/` にできた文書は公開されません。続けて `quarto render custom/<id>.qmd --to typst` を実行すると、表紙、目次、章番号の付いた1冊のPDFになります。公開している講座も同じ方法で1冊にできます（例：`course survey`）。

**値を更新する**：`_variables.yml` を直す。参照している全章に反映されます。

## 手元で確かめる

```
pip install pyyaml
python scripts/build.py check   # 章立ての点検
python scripts/build.py todo    # 未作成の章の一覧
python scripts/figures.py       # 図を作る
python scripts/build.py nav     # メニューを作る
quarto preview                  # サイトを表示する（Quartoが必要）
```

## 公開のしくみ

main が更新されると、GitHub Actions がサイトとPDFを作り直し、GitHub Pages に公開します。最初に一度だけ、リポジトリの Settings → Pages → Source を「GitHub Actions」にします。

## このリポジトリに置かないもの

公開リポジトリなので、次は置きません。

- 会員向けの内容（料金の比較表、価格の相場、仕様書のひな形の完全版）
- 顧客名、案件の内容、会員の情報、アンケートの回答
- 再配布が禁止されている資料、勤務先の社内資料
